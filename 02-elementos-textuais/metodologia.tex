\chapter{MATERIAIS E MÉTODOS}
Esta seção apresenta os materiais e os métodos utilizados no desenvolvimento do JurisFlow, uma plataforma web destinada ao gerenciamento de informações e atividades de escritórios de advocacia. São descritos o ambiente tecnológico utilizado, as etapas adotadas durante o desenvolvimento, o levantamento e a organização dos requisitos, a modelagem do banco de dados, a implementação do módulo inicial e os procedimentos utilizados para verificação do sistema.
A definição dos materiais e métodos foi realizada considerando as funcionalidades estabelecidas na proposta do projeto e o refinamento do escopo realizado durante o desenvolvimento. O sistema foi planejado para centralizar informações relacionadas a usuários, clientes, pastas, processos, diligências, prazos, notificações e histórico de atividades, buscando proporcionar maior organização e controle das informações do escritório.

\section{TECNOLOGIAS DE DESENVOLVIMENTO}

Para o desenvolvimento do JurisFlow, foi utilizada a linguagem de programação
JavaScript como principal linguagem para implementação da lógica da aplicação.
A escolha da linguagem está relacionada à sua ampla utilização no desenvolvimento
web e à possibilidade de empregá-la tanto no \textit{frontend} quanto no
\textit{backend}, permitindo a utilização de uma mesma linguagem em diferentes
partes da aplicação. Conforme apontam Cruz et al. (2018), o JavaScript deixou de
ser utilizado exclusivamente em aplicações executadas em navegadores e passou a
ser empregado também no desenvolvimento de outros tipos de software, incluindo
aplicações para dispositivos móveis e computadores. Essa característica contribui
para a utilização da linguagem em diferentes contextos de desenvolvimento.

Para a implementação do \textit{backend}, foi utilizado o ambiente de execução
Node.js. A tecnologia permite a execução de código JavaScript fora do navegador
e utiliza uma arquitetura orientada a eventos e operações de entrada e saída não
bloqueantes. Essa característica possibilita o desenvolvimento de aplicações
capazes de lidar com múltiplas requisições de forma eficiente. Segundo \citeonline{godinho2023}, 
a utilização do Node.js no desenvolvimento de estruturas de backend está
relacionada ao desempenho proporcionado pelo motor V8, desenvolvido pelo Google.
O ambiente permite a execução do JavaScript fora do contexto dos navegadores,
sendo utilizado no desenvolvimento de aplicações web. No JurisFlow, o Node.js foi
empregado na implementação das funcionalidades relacionadas ao processamento das
requisições e à comunicação entre a aplicação e o banco de dados.

O Ambiente de Desenvolvimento Integrado (IDE) utilizado foi o Visual Studio Code.
A ferramenta foi escolhida por oferecer um ambiente de desenvolvimento leve e
extensível, além de disponibilizar recursos e extensões voltados ao desenvolvimento
com JavaScript e Node.js. Também foram utilizados seus recursos de integração com
o Git, contribuindo para o controle e a organização do código durante o
desenvolvimento do projeto.

Para o controle de versão e a hospedagem do código-fonte, foi utilizado o GitHub
em conjunto com o Git. A ferramenta possibilitou centralizar os arquivos do projeto
e organizar o desenvolvimento colaborativo por meio do controle de versões. Também
foram utilizadas ramificações (\textit{branches}) para organizar as alterações
realizadas durante o desenvolvimento e facilitar o gerenciamento das diferentes
funcionalidades da aplicação.

Para o armazenamento e gerenciamento dos dados, foi utilizado o sistema gerenciador
de banco de dados PostgreSQL. A escolha de um banco de dados relacional está
relacionada à necessidade de estruturar e relacionar informações como usuários,
clientes, pastas, processos e diligências. Conforme aponta \citeonline{carvalho2017}, o
PostgreSQL apresenta características relacionadas à integridade, segurança e
consistência dos dados, aspectos relevantes para sistemas que trabalham com
diferentes entidades relacionadas.

Também foi utilizado o Docker como ferramenta de virtualização e conteinerização,
principalmente para a execução do banco de dados PostgreSQL. A utilização de
contêineres possibilitou padronizar o ambiente de desenvolvimento e reduzir a
ocorrência de diferenças de configuração entre os ambientes utilizados pela equipe.
De acordo com \citeonline{alencar2025}, ferramentas de conteinerização como o Docker podem
contribuir para minimizar inconsistências entre diferentes ambientes de
desenvolvimento, facilitando a configuração e a execução das aplicações.

O módulo apresenta dois atores responsáveis pela interação direta com suas
funcionalidades, além de um ator de destino relacionado à execução de uma das

Assistente Jurídico, é responsável por executar a ação de Forçar Criação da
Primeira Diligência, garantindo que, após a criação da pasta, seja registrada a
primeira atividade relacionada ao caso. O fluxo também contempla duas extensões
condicionais baseadas em regras de negócio. A primeira é Exigir Horário Específico,
acionada quando a categoria do caso corresponde a uma audiência, situação na qual
é necessário registrar, além da data, um horário específico para o compromisso.
A segunda é Atribuir Prazo Padrão de 30 dias, utilizada como comportamento de
\textit{fallback} quando não for informado um prazo maior, garantindo que nenhuma
diligência seja criada sem uma data de vencimento definida
(Figura~\ref{fig:casos-uso-diligencias}).

Além dos atores que interagem diretamente com o módulo, existe o ator Sistema
Automatizado, responsável pela execução de rotinas em segundo plano relacionadas
ao controle temporal das atividades. Entre suas responsabilidades está Disparar a
Régua Regressiva de Notificações, enviando alertas preventivos nos períodos de 7,
3 e 1 dia antes do vencimento, bem como no próprio dia do vencimento. O Sistema
Automatizado também é responsável por Varrer o Banco e Alertar sobre Pastas
Inativas, realizando o monitoramento periódico das pastas e processos cadastrados.
Quando uma pasta permanece sem atualização por período superior a 30 dias, o
sistema gera uma notificação para alertar a equipe responsável, contribuindo para
o acompanhamento contínuo dos casos e para a redução de processos sem movimentação.

\subsection{VISÃO GERAL DO PRODUTO}

O JurisFlow é uma plataforma web voltada para escritórios de advocacia,
desenvolvida com o objetivo de centralizar o gerenciamento de clientes, processos,
prazos, diligências e atividades. O sistema foi estruturado para reunir essas
informações em uma única plataforma, facilitando o acompanhamento das atividades
relacionadas aos casos.

O \textit{backend} do JurisFlow foi desenvolvido utilizando JavaScript e Node.js,
responsáveis pela implementação da aplicação e de suas funcionalidades. Para o
armazenamento dos dados, foi utilizado o PostgreSQL, executado em um ambiente
conteinerizado por meio do Docker.

\subsection{PERFIS DE USUÁRIOS E CONTROLE DE ACESSO}

O sistema foi estruturado considerando diferentes níveis de acesso, relacionados
às permissões atribuídas a cada perfil de usuário. Os perfis identificados são:

\begin{itemize}
  \item \textbf{Administrador Chefe:} responsável por gerenciar a equipe,
        configurar os parâmetros globais e cadastrar usuários.
  \item \textbf{Advogado:} usuário responsável pelo cadastro de clientes e pelo
        gerenciamento dos casos.
  \item \textbf{Assistente Jurídico:} auxilia nas atividades técnicas e jurídicas,
        possuindo algumas permissões semelhantes às do advogado.
  \item \textbf{Secretaria:} perfil destinado ao suporte operacional, consultas e
        rotinas administrativas.
  \item \textbf{Estagiário:} usuário destinado às atividades de apoio e
        aprendizado técnico-operacional.
\end{itemize}

\section{IMPLEMENTAÇÃO E VERIFICAÇÃO DAS FUNCIONALIDADES}

\subsection{MÉTODO DE IMPLEMENTAÇÃO}

O desenvolvimento do JurisFlow foi organizado em etapas, iniciando pela definição
do problema e das funcionalidades necessárias ao sistema, seguida pela análise dos
requisitos, modelagem do banco de dados e implementação do módulo inicial. O
processo iniciou-se com a definição da proposta da plataforma e das funcionalidades
consideradas necessárias para atender às demandas identificadas no contexto dos
escritórios de advocacia. Entre as funcionalidades inicialmente estabelecidas estão
o gerenciamento de usuários e perfis, cadastro de clientes, gerenciamento de pastas
e casos, controle de processos, controle de prazos e diligências, notificações e
histórico de atividades.

Durante o desenvolvimento, o escopo foi revisado para priorizar as funcionalidades
consideradas essenciais para a implementação inicial. Como resultado desse
refinamento, algumas funcionalidades foram retiradas ou postergadas, entre elas a
integração com Inteligência Artificial, o sistema de backup de documentos e o login
utilizando e-mail.

A metodologia adotada foi estruturada de maneira incremental, permitindo que as
funcionalidades fossem desenvolvidas e verificadas progressivamente. O processo
contemplou as seguintes etapas: levantamento e organização dos requisitos,
modelagem do sistema e do banco de dados, desenvolvimento, controle das alterações
e verificação das funcionalidades implementadas.

A implementação ocorreu de forma incremental, sendo a estruturação dos perfis e o
cadastro de usuários e clientes algumas das primeiras funcionalidades desenvolvidas.
